# 6.5 Your own StdIO

*6 The StdIO library*

A project can have its own `StdIO.cls`. It replaces the platform's, and `Print`, `Input`,
`Cls` ... in the rest of the project call it. Inside it, the statements are the built-in
ones, so it can add to the normal console:

<!-- file: StdIO.cls -->
**StdIO.cls**

```basic
' every line printed is counted, and text goes out in capitals
Public Lines As Integer

Public Sub PutStr(ByVal s As String)
  Print UCase$(s);
End Sub

Public Sub NewLine()
  Print
  Lines = Lines + 1
End Sub
```

**Main.bas**

```basic
Print "hello"
Print "world"
Print StdIO.Lines
```

```text
HELLO
WORLD
2
```

Only the methods the program uses must be there; a missing one is a compile error naming it.
Copy `src/lib/<platform>/StdIO.cls` into a project to start from the platform's own. See
`bas/ownstdio/`.

**Any library class can be replaced the same way.** A project file named `System.cls`,
`FileSystem.cls`, `Memory.cls`, `List.cls` or `Graphics.cls` is used instead of the platform's
class of that name:

- StdIO is the only one the statements go through (`Print`, `Input`, `Cls`, `Locate` ...).
  For the others, the calls `Memory.Alloc(...)`, `List.Append(...)` and so on go to your class
  by name.
- Only the methods your program calls must be in it.
- To tailor rather than rewrite, copy the platform's file from `src/lib/<platform>/` and
  change it: add methods, take out the ones you don't need, or change what one does. The
  library's assembly routines (`mem_alloc`, `lst_append` ...) are still there for your
  `#asm` blocks to call.
- There is no way yet to call the platform's own class from inside yours (a class can't
  pass a call on to the one it replaces): copy the methods you want to keep.
