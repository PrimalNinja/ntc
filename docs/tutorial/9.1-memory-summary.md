# 9.1 Memory: RAM while the program runs

*9 The Memory library*

The `Memory` class hands out RAM while the program runs: blocks from a heap (`Alloc` /
`Free`), and on the CPC whole 16K pages. `Option Memory` picks how it reaches the RAM; the
methods are the same either way, so one program builds with both.

| | `Small` | `CPCExpansion` |
|---|---|---|
| Platforms | every one; the default on cpm and test | cpc, cpcmin, cpcfw; their default |
| The heap | the free main RAM after the program | D pages (16K each) |
| RAM pages | none (`Pages()` = 0) | 1 (64K), 5 (6128), up to 257 (4MB) |
| The program | anywhere | must stay out of `#4000-#7FFF` (`Option Reserve &H4000, &H4000`) |

| Members | Page |
|---|---|
| `ProgramStart`, `ProgramEnd`, `Top`, `StackTop`, `HeapStart`, `HeapEnd`, `TableEnd` | [9.2](9.2-where-things-are.md) |
| `Alloc`, `Free`, `Largest`, `ReadByte`, `ReadWord`, `WriteByte`, `WriteWord`, `Copy`, `PageOf`, `Address` | [9.3](9.3-the-heap.md) |
| `Pages`, `FreePages`, `RamSize`, `Model`, `AllocPage`, `FreePage`, `SelectPage`, `CurrentPage`, `PageType`, `Map` | [9.4](9.4-ram-pages.md) |

Statuses: `Memory.OK` (0) and `Memory.BadPage` (-2: not a page this machine has, or not a
block in use). `Alloc` and `AllocPage` give 0 when there is no room - the program carries on
without (no music on a 64K machine, say).

Overlay classes (section [13](13.1-making-an-overlay-class.md)) work with both. With
`CPCExpansion` each overlay gets RAM pages of its own; with `Small` they take turns in one
overlay area at `#4000-#7FFF` ([13.5](13.5-one-overlay-area.md)), and the heap then stops at
`#4000` - so on CP/M a program can be bigger than the TPA, its parts loaded from disc as needed
(page [12.3](12.3-overlays.md)).

The example `bas/memmap.bas` shows all of it.
