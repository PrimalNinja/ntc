# 13.2 Building and shipping the files

*13 Class overlays*

One compile builds the program and every overlay file. Assembling writes them all:

| Platform | Program | Overlays |
|---|---|---|
| cpcmin, cpcfw | `NAME.BIN` | `NAME.001`, `NAME.002` ... with an AMSDOS header (binary, loads at `#4000`) |
| cpm | `NAME.COM` | `NAME.001`, `NAME.002` ... the plain bytes |

The page files take the program's name (the project's name), numbered in the order of the pages
in the source - so two programs on one disc never overwrite each other's. A page named with an
extension, in quotes, keeps that name: `Option Class Overlay "LEVEL1.PAG"`. The compiler's layout list
says which number each page got.

Every page file carries the build's stamp: a file left over from an older build is refused
("The file is from another build", `Load()` gives -14) - copy all of them after each build.

Put the page files on the disc next to the program. On the CPC add `Option RomEnable 7`: after
`RUN"` AMSDOS is gone until the program starts it again, and the overlays would be looked for
on tape.

The disc images in `src/build/dsk/` have `OVERLAYS` with `OVERLAYS.001` and `OVERLAYS.002` on the
cpcmin, cpcfw and cpm discs.

The program must end below `#4000`: overlays run at `#4000-#7FFF`. The assembler checks it. Each
overlay's code (with its paged variables) must fit in 16K.
