# 1.3 Modules

*1 The IDE and projects*

A module is a `.bas` file. A project has one or more.

Statements outside any procedure are the main program. They run from the top, like classic
BASIC. If there is a `Sub Main`, the compiler calls it when they reach their end - nothing
has to call it.

```basic
Print "starting"

Sub Main()
  Print "in Main"
End Sub
```

```text
starting
in Main
```

- No top level statements: `Sub Main` runs straight away (as in VB, where the program starts
  in `Sub Main`).
- Top level statements that end with `End`: `Sub Main` never runs.
- Calling `Main` yourself from the top level runs it twice: your call, then the automatic one.

VB has no top level statements at all (they are an error there); NTC allows both styles.

A module's name is its file name (or `Attribute VB_Name = "..."` if the file has one, as VB
files do). Names declared `Public` (or `Global`) are seen by every module; `Private` (and
`Dim` at the top of a module) only inside it. A name can always be given in full as
`Module.Name`.

<!-- file: Tools.bas -->
**Tools.bas**

```basic
Public Total As Integer

Public Sub AddUp(ByVal n As Integer)
  Total = Total + n
End Sub
```

**Main.bas**

```basic
AddUp 5
AddUp 7
Print Total; " "; Tools.Total
```

```text
12 12
```

The main program can be in any module: the first one with top level statements starts.
