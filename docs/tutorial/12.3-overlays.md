# 12.3 Overlays

*12 Paging and overlays*

An **overlay** is part of a program that isn't in memory all the time: it is loaded from disc
when it is needed, into memory another overlay may have used before. A program can then be
bigger than memory - a level, a menu, an editor at a time.

NTC builds overlays from classes: `Option Class Overlay Level1` at the top of a `.cls` puts its
code in its own file (page Level1, file `PROGRAM.001`), built in the same compile. Calling it loads it. Section 13
goes through it.

There are two ways an overlay is kept, depending on `Option Memory`:

| | RAM pages (`CPCExpansion`) | One overlay area (`Small`) |
|---|---|---|
| Platforms | cpcmin, cpcfw on a 6128 or more | cpm; cpcmin, cpcfw with `Option Memory Small` (also 64K) |
| Where | each class in its own 16K page | `#4000-#7FFF`, one class at a time |
| First call | loads the file into a free page | loads the file into the area |
| Later calls | switch its page in: no disc | free if it is still there, else load it again |
| Overlay calling overlay | switch pages | load each way |

The program's own variables stay in main memory in both, so they keep their values whatever is
loaded.
