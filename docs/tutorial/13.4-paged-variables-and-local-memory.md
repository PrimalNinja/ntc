# 13.4 Paged variables and local memory

*13 Class overlays*

With RAM pages (`CPCExpansion`), an overlay's page has room left after its code. Two ways to
use it:

**Paged variables** - `Private Paged` (or `Dim Paged`) puts a variable in the overlay's page
instead of the program's memory. It starts fresh (0, "") each time the class is loaded: right
for a level's own data.

<!-- file: Shop.cls -->
**Shop.cls**

```basic
Option Class Overlay Shop
Private Paged stock(99) As Integer       ' 200 bytes, not in the program
Public Spent As Integer                  ' an ordinary variable: in the program
Public Sub Buy(ByVal item As Integer)
  stock(item) = stock(item) - 1
  Spent = Spent + 1
End Sub
```

<!-- platform: cpcfw -->
**Main.bas**

```basic
Option RomEnable 7
Option Reserve &H4000, &H4000
Shop.Buy 3
Print "spent "; Shop.Spent
```

**Local memory** - the rest of the page: `LocalStart()` and `LocalSize()` say where;
`LocalAlloc(size)` / `LocalFree(address)` hand out blocks of it. Only from the class's own code.

<!-- nocheck -->
```basic
Public Sub Enter()
  Dim buf As Integer
  buf = LocalAlloc(1000)          ' an address in the page, 0 = no room
  Print "room left after the code: "; LocalSize()
End Sub
```

In one overlay area ([13.5](13.5-one-overlay-area.md)) the class doesn't stay, so `Paged`
variables are ordinary ones (they keep their values) and local memory is fresh at each load.
