# 12.4 Choosing a memory model

*12 Paging and overlays*

| You have | Use |
|---|---|
| a program that fits, no big data | nothing: the defaults |
| big data (tables, records, text) | a List ([10](10.1-list-summary.md)): it uses RAM pages on a 6128 by itself |
| data you load and switch: music, levels, graphics | `Memory.AllocPage(TypeUser)` + `FileSystem.Load` ([9.5](9.5-filling-a-page.md)) |
| too much code for memory, a 6128 or more | overlay classes with `CPCExpansion` (the default on cpcmin / cpcfw) |
| too much code, on CP/M or a 64K CPC | overlay classes with `Option Memory Small`: one overlay area |
| every byte for the program, no paging | `Option Memory Small`: the smallest Memory code |

Rules of thumb:

- Ask, don't assume: `Memory.Pages()`, `AllocPage` giving 0, `System.HasCapability("PAGES")`.
- Keep the program out of the window when it pages: `Option Reserve &H4000, &H4000`.
- Group code that calls itself a lot into one overlay class: calls between overlays in one
  overlay area cost a disc load each way.
