# NTC on the 45GS02 - the MEGA65 (`m65`)

(c) 2026 Cyborg Unicorn Pty Ltd - MIT License

The `m65` platform compiles NTC BASIC for the MEGA65: a 45GS02 thread, 45GS02 keywords, a PRG
that BASIC 65 loads and RUNs. The compiler is the same one; the 45GS02's parts are switched on by
the platform file's `;@cpu 45gs02`.

---

## 1. NTC on a 45GS02

A plain 6502 can't run NTC's threaded code well: its stack pointer is 8 bits and stuck in page 1.
The 45GS02 has what it takes:

- **SP = the instruction pointer.** `CLE` makes SP 16 bits, so the stack can be a thread anywhere
  in the 64K. `rts` pulls a word and jumps to it plus 1, so a thread word is the keyword's address
  less 1: `dw kw_ltov-1, 10, var_x`. SP always points one byte before the next word. A label put
  in SP is label - 1 (the branch keywords, `ntc_go`, take the 1 off at run time).
- **A keyword takes its arguments off the thread** left to right with `NTC_POP zp` (two `pla`
  into a base page word), and ends with `rts`.
- **No `jsr`, `pha`, `php` on the thread.** `NTC_RS` keeps the thread position in `ntc_ip` and
  loads the real stack (`ntc_csp`), `NTC_TS` puts the thread back; both use X and Y, so set X
  after `NTC_RS`, not before. The three macros are at the top of every program.
- **Compares** leave Z set for true, as on the Z80 (`lda #0` true, `lda #1` false at the end).
- **The base page** ($00xx, `TAB` 0) holds the library's work registers: `ntc_ip` $02, `ntc_csp`
  $04, `z_p0`-`z_p5` $06-$10 (pointers), `z_a`-`z_g` $12-$1E (words), `z_l0`-`z_l3` $20-$2C
  (Longs), `z_t0`-`z_t7` $30-$37 (bytes), `z_q0` / `z_q1` $40 / $44. The platform uses $50-$6F;
  $70-$FF are free for a program's `#asm`.
- **Multiplying** uses the MEGA65's hardware multiplier ($D770-$D77F): Integer and Long `*`, and
  the fixed point work in a game's own `#asm` can use it too. Dividing is in software.

### One mode, interrupts off

An interrupt pushes onto the stack - the thread - so the MEGA65's interrupts are off all the time:
the CIAs' and the VIC's are switched off at the start, and the NMI (RESTORE, CIA 2) is blocked by
leaving a CIA 2 NMI unacknowledged (the 6502 only takes an NMI on its edge). There is one mode:
every keyword is the turbo one, `Turbo On` / `Turbo Off` compile to nothing, and the start mode is
always turbo. `Frame` and `Ticks` use the VIC-IV's frame counter instead of an interrupt.

### What isn't there yet

Pages and overlay classes (`Option Page`, `Option Class Overlay`: an error says so), the `Memory`,
`List`, `FileSystem` and `Graphics` classes, the `Interrupt` statement and interrupt classes,
`Library: ROM`, colour text on the console. `#If NTC_M65 Then` picks a 45GS02 `#asm` block over a
Z80 one. Pages are the next step: the MEGA65's MAP instruction gives 8K blocks of its 384K chip
RAM in the 64K, so `Option Page Name Loaded n` can work as it does on the CPC and the Next.

## 2. The MEGA65 platform

### Memory

| Where | What |
|---|---|
| $0000-$00FF | the base page (above) |
| $0400-$07EF | the real stack (SP starts at $07EF) |
| $07F0 | three bytes for the test tools: columns, rows, $A5 when the program has ended |
| $0800-$0FFF | screen RAM: the console (80 x 25) |
| $1000-$17FF | the second screen RAM (the `Vic` class) |
| $1800-$1FFF | the `Vic` class's text layer: the characters, then their colours |
| $2001 | the program: a BASIC line (`10 BANK 0 : SYS 8209`), the start code, `ntc_start`, the threads, the stubs, the `#asm` blocks, the literals and strings, the variables, the library |
| after it - $CFFF | the arrays (`kw_bssinit` stops with an error past $D000) |
| $D000-$DFFF | I/O |
| $E000-$E7FF | the font (font8x8_basic, public domain: ASCII 32-127) |
| $E800- | the `Vic` class's tables (the dirty flags of the text layer) |
| $40000 / $50000 | the `Vic` class's two picture buffers (64000 bytes each) |
| $10000 | a `--log` test build: the console's transcript (its length at $1FFFC) |

### The start

The VIC-IV's registers knocked on, MAP reset, the base page at 0, the ROMs out (`$01` = $35, $D030
= 0), the 16 bit stack at $07EF, the CIAs' ports set to inputs (the joysticks), any keys left in
the keyboard queue dropped, every interrupt off and the NMI blocked, 40MHz, the font copied to
$E000, then the console (below) and `ntc_start`.

### The console

80 x 25 text, PAL, white on black. `Print`, `Locate`, `Cls`, `Tab` work as everywhere; `Mode 2`
is 80 columns, any other mode 40 (both clear the screen). While the `Vic` class's
screen is on, `Print` goes to its 40 x 25 text layer instead.

### Keyboard and joysticks

`Inkey`, `Input` and `StdIO.GetKey` read the MEGA65's ASCII keyboard queue ($D610): RETURN 13, DEL
8, the cursor keys &HF0-&HF3 (the CPC's codes). `Joy.Read(n)` reads joystick port n (1 or 2):
`Joy.Up` 1, `Down` 2, `Left` 4, `Right` 8, `Fire` 16, set while held.

### Frame, Ticks

`Frame` waits for the next frame (the VIC-IV's frame counter at $D7FA moves on). `Ticks` counts
frames, 50 a second.

### The platform classes (`lib/m65/`)

Each method is one `#asm` block, so each is a keyword.

| Class | Members |
|---|---|
| `Vic` | `Screen onoff`, `Field cols`, `Color n, rgb` (&HRGB), `Colors addr, first, count`, `Images addr`, `Sprite n, x, y, img, attr`, `Hide n`, `HideAll`, `Update`, `Draw`, `Stamp img, x, y, attr`, `Box x, y, w, h, colour`, `Pen colour`, `Paper colour`, `Back colour`, `Star n, x, y, colour`, `Stars n`, `StarScroll y`; constants `FlipX`, `FlipY`, `Palette`, `Sprites`, `Width`, `Height` |
| `Joy` | `Read(n)`; constants `Up` ... `Fire` |
| `Sid` | `Play channel, period, slide, volume, frames` (channels 0-2 tones on SID 1, 3 noise on SID 2; a slide a frame, a fade), `Stop channel`, `Quiet`, `Busy(channel)`, `Update` (once a frame) - the same as the Mega Drive's `Psg`, so a game's sound moves across unchanged |
| `StdIO` | the console, as on every platform |
| `System` | the same members as everywhere: `Platform` = "M65", `TicksPerSecond` = 50, `CpuClock` = 40500 ... |

**The `Vic` class.** The MEGA65 has 8 hardware sprites, not enough for an arcade game, but a fast
CPU, DMA and lots of RAM. So `Vic.Screen 1` turns on a game screen drawn by the CPU: 320 x 200 in
the VIC-IV's full colour character mode (each 8 x 8 character is 64 bytes, a byte a pixel, 256
colours), in two buffers at $40000 and $50000. Once a frame `Vic.Update` draws the next picture
into the buffer not on show - the playfield cleared by the DMA chip, up to 64 stars, the sprites
(80: 79 first, so sprite 0 is in front, clipped to the playfield), the text layer's changed cells -
then waits for the frame and shows it. The playfield is the left `Vic.Field` columns; the panel
to its right is kept, and `Vic.Stamp` / `Vic.Box` draw into it in both buffers.

An image (`Vic.Images` gives a table of their addresses) is w, h (pixels, h even, up to 32), then
w columns of h / 2 bytes, two pixels a byte (the low nybble the upper pixel): 0 clear, 1-15 shown
as colour 16 + the sprite's palette * 16 + it. Colours 0-15 are the C64's; `Vic.Color` sets
16-255. `bas/cyswarm_m65/tools/cyswarm_gfx.py` writes images in this form.

Speed: the start of `Vic.Update` (the clear, the stars, the text) takes about a tenth of a frame;
16 sprites of 16 x 16 about a third. `bas/cyswarm_m65` draws 44 enemies, the fighters, shots and
the beam at 50 frames a second.

## 3. Building and testing

### Tools

- **vasm**, 6502 oldstyle syntax: http://sun.hasenbraten.de/vasm/ (2.0f),
  `make CPU=6502 SYNTAX=oldstyle`. Its `-mega65` option gives it the 45GS02's instructions.
  `NTC_VASM65` gives `m65build.py` its path. The assembly is
  `vasm6502_oldstyle -mega65 -opt-branch -Fbin`.
- **To test without a machine**: Xemu's xmega65 (https://github.com/lgblgblgb/xemu) with NTC's
  test driver, `test/xemu/`:

  ```
  git clone https://github.com/lgblgblgb/xemu && cd xemu
  git apply /path/to/ntc/test/xemu/xemu-ntctest.patch
  cp /path/to/ntc/test/xemu/ntctest.c targets/mega65/
  make            (needs libsdl2-dev)
  ```

  The patch adds `ntctest.c` (driven over two pipes: run N frames, load a file into RAM, jump,
  the joystick, keys, a screenshot, read RAM), calls it at the end of every frame, lets it hold
  the joystick, and lets Xemu run as root (the test container). It was made against Xemu commit
  40dfef0. `NTC_XEMU` gives the tools the path of `build/bin/xmega65.native`. Xemu needs no ROM
  for this: `m65run.py` starts it with `-headless -sleepless -usestubrom -nosound -virtsd`, gets
  past the hypervisor's first screen, loads the PRG into RAM and jumps to its SYS address.

### Build

```
python3 test/m65build.py bas/m65_test/Main.bas bas/m65_test/Counter.cls --out=M65TEST.PRG
```

`m65build.py` runs `test/cli.js --platform=m65`, assembles, and puts the load address in front.
`--log` makes a test build, `--list=` writes vasm's listing (the game bot reads variables by its
labels). The IDE (platform "MEGA65") writes the same assembly.

### Run

```
python3 test/m65run.py M65TEST.PRG --frames=600 --joy=100:F,104:- --keys=200:~ --shot=out.png --text
```

`--joy=frame:buttons` (U D L R F, `-` none) holds the joystick from that frame on;
`--keys=frame:text` types keys, one a frame (`~` = RETURN); `--shot` / `--shots=f1,f2:prefix`
take pictures (the 320 x 200 screen, doubled);
`--text` prints the console; a `--log` build keeps the console's transcript in RAM and
`--log --untilend` prints it once the program ends.

### Tests

`test/m65regress.sh` builds and runs `bas/m65_test` (163 checks: constants, Enum, maths and its
edges, logic, Long, every string function, arrays, Type and With, the flow statements, procedures,
a class, AddressOf / VarPtr / Peek / Poke, a 45GS02 `#asm` block and asm keyword functions, the
hardware multiplier, Frame and Ticks, System, Inp / Out, Column / Cols), then the VB self tests
that fit (vb_test, 2, 3, 4, 6, 7, 8, 9, Long, the function arguments, the class demo, the sieve).
All pass. vb_test5, 10 and 11 have Z80 `#asm` in them.

The Z80 and 68000 platforms' output is unchanged: the example programs compile byte for byte as
before.

Not checked: everything has run on Xemu only, not on a real MEGA65. Xemu's 45GS02 timing is
close to the real one, not exact. The SIDs have not been listened to.

## 4. In the compiler (`js/ntc_compiler.js`)

All behind `blnM65` (set from the platform's `;@cpu 45gs02`):

- the library is `NTC_LIB_ASM_M65` (`asm/ntc_lib_m65.asm`, put in `js/ntc_lib.js` by `gen.js`);
- one mode: the start mode is always turbo, `Turbo On / Off` emit nothing, `exitCode` is `rts`;
- the header: `org $2001`, then the platform's `ntc_m65_stub` (the BASIC line) and
  `ntc_m65_boot` (the start code must be in low memory: the ROMs hide $A000 up until it has run),
  the `NTC_RS` / `NTC_TS` / `NTC_POP` macros;
- `ntc_start`: the real SP into `ntc_csp`, SP = `main_thread` - 1, `rts`;
- thread words `dw label-1`; GOTO stubs load SP; GOSUB stubs keep the thread position;
- `procStubs65`, `stubStrCopy65`: the call and return stubs;
- `#asm` blocks end with `rts`; `txs` / `tys` count as a branch (not an asm keyword);
- a last pass turns `#hex` into `$hex` in the data lines (vasm's oldstyle syntax).
