NTC BASIC - build info
=======================

Build number: YYYYMMDD-N
  YYYYMMDD is the UTC date the archive was built. N starts at 1 each day and is
  incremented by 1 on EVERY build, whether or not that build was taken (applied).
  The number counts builds, not releases.

Maintaining this file
  - On every build, add a NEW entry at the TOP of the history below (newest first).
  - The entry heading is the build number: today's date, with N one higher than
    the highest N already used for today (1 if today has no entry yet).
  - Under the heading, list that build's changes as dot points.
  - Do not edit or delete older entries - they are the history.

Packaging rule (what goes in the archive) - READ THIS BEFORE ZIPPING
  - INCLUDE all source AND all tooling. Tooling means everything under tools/ and
    its dependencies, INCLUDING node_modules (e.g. tools/coleco/node_modules),
    src/3p, hosted/3p, _old, build.bat, and the generated build/ (ASMs, ROMs, the
    .dsk disc images). Do NOT strip node_modules or any tools/ content - the
    coleco build needs its node_modules and it has been dropped by mistake before.
  - test/out and test/t are KEPT, not scratch - never drop either folder. test/out
    ships POPULATED (the suite's per-program .asm/.bin/.sym for each platform/mode,
    regenerated from a clean run). test/t ships with its dirs (test/t, test/t/files)
    PRESENT but the run files cleared. EXCLUDE only genuine scratch: any __pycache__/,
    a top-level t/, and the VCS .git/. build/ is regenerated each build, not hand-carried.
  - REGENERATE the derived folders whenever the compiler, library (.cls) or
    flavours change: node test/gen.js (rebundles src/js/ntc_lib.js), node
    test/genbuild.js + test/genrom.js + test/gendsk.sh (rebuild build/), and node
    tools/hosted/build.js (rebuilds hosted/ - the web IDE that bundles the compiler).
  - Do NOT ship a .gitignore that excludes build/ (or any tooling). build/ is a kept
    deliverable; a .gitignore with a build/ line silently drops the whole build folder
    from a git-based release. This archive ships no .gitignore.
  - When in doubt, keep it. Dropping a tracked file is the error to avoid.

20261106-1
----------
Bug fix (the second bug from the 20261105-12 report, left open in -13)
- A public pure-#asm method in a page / overlay class (it becomes an asm keyword), called from
  OUTSIDE its page (from main or from another page), is now switched in correctly. Before, the far
  call emitted a bare dw fn_x with no page switch, so the keyword ran against whatever happened to
  be in the #4000 window.
- The far call is now bracketed in the thread:
      dw ntc_ovl_kwin, <class block>, fn_x, args..., ntc_ovl_kwback
  ntc_ovl_kwin saves the page currently in the window and switches the class's page in (loading its
  file into a free page first if needed, via ntc_ovl_core); the keyword body then runs with its own
  page mapped, reads its inline args and rets into the thread as usual; ntc_ovl_kwback switches the
  saved page back. A call from the keyword's own page stays a bare dw fn_x (local, no switch), so
  nothing changes for same-page calls.
- Only USER keywords are wrapped. The compiler-added lifecycle members (Load / Unload / Loaded /
  Page / LocalStart / LocalSize / LocalAlloc / LocalFree) are asm keywords too, but their bodies
  stay in main memory and run while the class is NOT loaded, so they must NOT be switched - they are
  excluded, the same rule asmInBank already uses. (Missing this exclusion wrongly force-loaded an
  overlay on a Loaded() / Page() call and broke the overlay/pages suite; with it, all pass.)
- Scope: single-page classes. A class copied into several pages, far-calling its keyword, still
  keeps the bare dw (documented limitation, tutorial 13.6).
- Both overlay models: CPCExpansion (RAM pages) and Small (one overlay area at #4000). The two
  primitives ntc_ovl_kwin / ntc_ovl_kwback are added to both in src/asm/ntc_lib_cpc.asm, and to
  NTC_ROM_RUNTIME so a Library: ROM build exports them (registry gained 2 names on each CPC ROM).
- Files: src/js/ntc_compiler.js (the asm-keyword call site wraps a far, single-page, non-lifecycle
  user keyword), src/asm/ntc_lib_cpc.asm (the two primitives in each model), src/js/ntc_lib.js
  regenerated. test/pkf added (Sub + Function far keywords, one with an arg); test/regress.sh runs
  it on cpcmin (RAM pages) and cpm (one overlay area), both modes. Tutorial 13.6 notes the
  behaviour and the single-page limitation.
- build/ (ASMs, ROMs, .dsk) and hosted/ regenerated with this compiler. Full regression: 945 ok,
  0 fail.

20261105-13
-----------
Bug fix (from the 20261105-12 bug report)
- A class copied into two or more pages, with a procedure nothing calls, no longer fails to
  assemble. The copy table (p_<class>_<proc>_ct) was built for every entry in objStubClass,
  including a procedure whose body was never emitted (unused), so the table named a label that
  did not exist ("Label not found"). compileUnused compiles the unused procedure into a throwaway
  buffer to resolve its declarations, then truncates the body and stub back out - but it did not
  drop the objStubClass entries that throwaway compile had registered. It now does, so no table is
  written for a body that is not emitted. (src/js/ntc_compiler.js: compileUnused saves and restores
  objStubClass, like it already does for objProcStubDone / objDecl / objFastUse.) test/copypage
  added; test/regress.sh checks it assembles clean.
- NOT fixed, needs a careful follow-up: the other reported bug - a pure-#asm Sub in a page (it
  becomes an asm keyword) called from OUTSIDE its page with a bare dw fn_x and no page switch. The
  root cause is that an asm keyword's body runs with SP = the thread and returns straight back into
  the thread (ret), so there is no clean point to switch the page back after it. The simple
  approach (make such a Sub a normal overlay procedure so it gets the switch stub) breaks asm
  keyword FUNCTIONS (the result convention) and local calls - it crashed the pagekw test. The real
  fix wraps a far call with switch-in / switch-back thread steps (new overlay keywords), which is a
  cross-platform threading change to do with on-hardware validation. Workaround until then: put one
  BASIC line in the Sub (it then gets a stub and the page is switched in), as the report notes.
- Additive: programs not hitting the copied-class case compile byte-for-byte as before; build/ and
  test/out carried from 20261105-7/-12 (no program in the suite triggers the fixed case, so output
  is unchanged); hosted/ regenerated. Full regression: 941 ok, 0 fail.

20261105-11
-----------
New: one directive for the memory map - Option Memory <kind> start, size, ...
- Option Memory Available | Reserved | Paged | Safe  start, size [, start, size] ... declares the
  memory map, one kind per line, as many lines as you like. It is the address side of what used to
  be spread across three directives:
    * Reserved  - program stays out of the range, built round it (= old Option Reserve).
    * Paged     - the window where RAM pages / overlays swap in at run time (= the old window form).
    * Safe      - always-mapped RAM where the safe classes go (= old Option Safe Areas); which
                  classes is still said with Option Safe "NAME" = Class, ...
    * Available - usable RAM (the default; for documenting a map).
  Proven on cpcmin (emulator): Option Memory Safe &H3000,&H0800 + Option Safe "BANK" = Bank places
  Bank at #3000 and Bank.Add(10,20) returns 37 - identical to the Option Safe Areas form.
- It reuses the window / safe-area / reserve machinery already in the compiler, so it is a new
  front end, not a new layout engine. It is a DIFFERENT word from the heap-scheme form (Option
  Memory Small | CPCExpansion n), which still works unchanged - the two do not clash.
- This is ADDITIVE: the old Option Reserve / Option Safe Areas / Option Page window forms still
  work; nothing is removed yet. Removing them (and Option HighCode / Option Place, and migrating
  the programs and CyborgOS C0 that use them) is the follow-on, to be done as a deliberate
  migration so the whole codebase does not break at once.
- src/js/ntc_compiler.js: the region form parsed in scanPages (maps to arrReserve / arrSafeAreas /
  the window); the scheme-form reader skips the region kinds. test/safe/MMain.bas added;
  test/regress.sh: five Option Memory checks (safe placement + run, odd-pair and unknown-kind
  refusals, scheme-form still works). docs/NTC.md documents it.
- Additive otherwise: programs not using the new form compile byte-for-byte as before; build/ and
  test/out carried from 20261105-7; hosted/ regenerated. Full regression: 936 ok, 0 fail.

20261105-10
-----------
Option Safe now PLACES the safe code (was validate-only in 20261105-9)
- The safe classes' code is laid into the first Option Safe area and the program is built round it,
  the same way it is already built round Option Reserve ranges and the paging window (holeLayout):
  each safe class's code is bracketed (; @safe ... ; @endsafe) and pulled into the safe area from
  its start, a ds pads up to it, and the rest of the program flows around. An ASSERT at assembly
  refuses it if the safe code does not fit the first area (enlarge Option Safe Areas). The code
  runs in place from the safe area.
- Proven end to end on cpcmin (emulator): a safe class Bank placed at #3000-#37FF, called from
  main, Bank.Add(10,20) returns 37; its body symbol is in the area and nothing else intrudes.
- Scope: this is the general layout (holeLayout: cpcmin, cpm, ...). Option HighCode's own layout
  (highLayout), which CyborgOS C0 uses, does NOT place safe code yet - that is the next step and
  needs on-hardware / emulator validation for C0. Multi-area packing (spilling into the 2nd and
  later areas) is also not done - all safe code goes in the first area for now (the ASSERT catches
  an overflow).
- src/js/ntc_compiler.js: compileProc brackets a safe class's code with ; @safe / ; @endsafe;
  holeLayout extracts it (arrSafeData), adds each Option Safe area as a hole (the first holds the
  code), and places the block from the area start with a fit ASSERT, including the case where the
  program ends below the area (placed just before ntc_end so it is inside the loaded image).
- test/safe/ (Bank.cls, Main.bas) added; test/regress.sh: two placement checks (symbol in the
  area, and it runs returning 37) on top of the five Option Safe refusals and the clean compile.
  docs/NTC.md updated.
- Additive: programs without Option Safe compile byte-for-byte as before; build/ and test/out
  carried from 20261105-7 unchanged; hosted/ regenerated. Full regression: 931 ok, 0 fail.

20261105-9
----------
Reworked Option Safe (the 20261105-8 form was wrong - it took class names and only guarded)
- Option Safe now matches the design: it names the SAFE MEMORY (the base RAM that stays mapped
  whatever bank is in the window) and the classes whose code must live there. Two forms, told
  apart like Option Page's two forms (a number vs a name):
    * Option Safe Areas = start, size [, start, size] ...  - declares the safe memory, as address
      and size pairs. Like Option Reserve but opposite: Reserve is memory the program stays OUT of;
      Safe is memory the program DOES build in, that stays mapped. Areas is a reserved word (no
      class may be named Areas). E.g. Option Safe Areas = &H1000, &H3000, &H8000, &H1000.
    * Option Safe "NAME" = Class [, Class] ...  - the classes whose code must go in safe memory
      (the banking / slot-access code). Same shape as Option Page "NAME" = classes.
- Refused: a safe class also in an Option Page / Option Class Overlay (code is a page OR safe,
  never both); safe classes with no Option Safe Areas to go in; a malformed Areas list (not
  address,size pairs); a "NAME" group naming a class not in the project; "Areas" used as a group
  name.
- Placement note: putting the safe classes in the safe areas takes effect once non-safe code is
  allowed to run in the window (the build-through-window reclaim). Until that exists the window is
  a reserved hole and ALL code is already in safe RAM, so this build validates the directive but
  moves nothing yet. The build-through-window layout change is the next step (needs on-hardware /
  emulator validation for CyborgOS C0).
- src/js/ntc_parser.js: the Option Safe value is captured. src/js/ntc_compiler.js: arrSafeAreas /
  arrSafeOrder / objSafe, parsed in scanPages next to Option Page, with the conflict and
  not-in-project checks. test/regress.sh: six Option Safe checks (the five refusals above and a
  clean areas+group compile). docs/NTC.md documents both forms.
- The 20261105-8 class-name guard form is removed. Additive otherwise: programs without Option
  Safe compile byte-for-byte as before; build/ and test/out carried from 20261105-7 unchanged;
  hosted/ regenerated. Full regression (test/regress.sh): 929 ok, 0 fail.

20261105-8
----------
New in this build
- New directive: Option Safe <class> [, <class>] ... - pins a class resident, keeping its code out
  of the pageable window #4000-#7FFF so it stays visible while a page is switched in. This is for
  the banking / slot-access code: the routines that select a bank into the window must not live in
  the window (they would vanish mid-switch). Safe is the black-and-white opposite of a page - code
  is either a page (flows into the window on demand) or Safe (resident), never both:
    * a Safe class that is also in an Option Page / Option Class Overlay is refused, naming the page;
    * a Safe name that is not a class in the project is refused;
    * Option Safe on an already-resident class (in no page) is accepted and changes nothing by
      itself - its job is the guard that stops that class ever being paged.
  (src/js/ntc_parser.js: the Option Safe rule; src/js/ntc_compiler.js: objSafe, and the check after
  the option records are read and scanPages has classified the classes.)
- test/regress.sh: added three Option Safe checks (paged Safe refused, unknown Safe class refused,
  a resident Safe class compiles clean). docs/NTC.md documents the directive.
- Additive change: Option Safe is inert unless used, so every existing program compiles byte-for-
  byte as before; build/ and test/out are carried from 20261105-7 unchanged (identical output).
  hosted/ regenerated (node tools/hosted/build.js) so the web IDE's bundled compiler/parser carry
  Option Safe. Full regression (test/regress.sh): 926 ok, 0 fail.

20261105-7
----------
New in this build
- Paging: a sub called only from inside its own page no longer routes its call through main. Its
  whole setup/return stub (the arg-pop, local-zero, body-enter and return) is now emitted IN the
  bank, next to the sub's body, so a call between methods of a page (same class, or classes
  grouped into one Option Page) stays in the bank - no main-memory stub for it. Only subs reached
  from main, another page, or a Tick / interrupt hook / AddressOf keep their stub in main (a far
  caller must reach it before the window is switched). The effect: main is spent only on the few
  entry points main actually calls, not on every paged method - so a page of dozens of internal
  methods (a game level, a CP/M-style numbered driver) costs main only its public entry.
  (src/js/ntc_compiler.js: objFarCalled from the call graph; procStubs routes a local-only,
  single-page sub's stub to the bank; composePages emits it in the page's local-entry region.)
- Correctness for copied classes: a class copied into several pages is treated as a far caller
  from each copy whose page lacks the callee (even when another copy is local), so a callee
  reached far from any copy keeps its main stub. (Verified on the pages fixture: Shared is copied
  into LEVEL1+LEVEL2 and calls OnlyOne, which is only in LEVEL1 - OnlyOne.Ten correctly stays in
  main while Level1/Level2's own private helpers move to their banks.)
- test/regress.sh: added a check that a local-only sub's stub lands in the bank and a dual-called
  sub's stays in main. docs/NTC.md documents the placement rule.

20261105-6
----------
Fix to the 20261105-5 directive (that build had Option Page 0 wrong)
- Option Page <startbank>, <addr>, <size> now ALWAYS reserves the window and builds the program
  round it - exactly what Option Reserve does - for every startbank, 0 included. It is "reserve
  PLUS more": the reservation, plus marking the region a page and choosing the banking offset.
  20261105-5 wrongly made startbank 0 skip the reserve (NTC_WINHOLE 0), which left the program
  running straight through the window - the "program must stay out of #4000-#7FFF" ASSERT fired,
  and the page call/return stubs (p_*_c / _in / _r), library and variables could land in the
  window. Now startbank 0 reserves like the rest; a paged build with Option Page 0 compiles and
  the stubs/library/variables all sit below #4000 (verified on the pages fixture: every p_*_c/
  _in/_r symbol is out of #4000-#7FFF).
- startbank is still 0-based (0 = the window's own 16K / #7FC0 / gate #C0 as page 0; >=1 keeps
  lower banks fixed, 1 = CPC double-buffer). The banking offset for >=1 reserves as 0 does for
  now; the offset itself is not yet distinct in the output.
- test/regress.sh: the Option Page checks now assert NTC_WINHOLE 1 for 0 and 1 alike, plus a new
  check that with Option Page 0 and a paged class every page stub stays out of the window.
  docs/NTC.md rewritten to say the directive reserves (reserve plus more), not "no hole".

20261105-5
----------
New in this build
- New directive: Option Page <startbank>, <addr>, <size> (e.g. Option Page 0, #4000, #4000).
  Declares the paging window as a page instead of the compiler auto-reserving it. A numeric
  first token tells it apart from Option Page Name = classes. startbank is 0-based - the first
  16K bank paging runs from, counting the window's own 16K (setting #7FC0 / CPC gate #C0) as
  bank 0:
    0 -> that bank is page 0: the window is a usable swap page, the 16K reclaimed, no hole
         (NTC_WINHOLE 0).
    1 -> the window kept fixed and built round (NTC_WINHOLE 1), paging from the next bank up
         (#C4) - the CPC double-buffer case, the former default behaviour.
  Same meaning on CPC, ZX Spectrum Next and MSX (the window is page 1 in the shared #7FC0-based
  model; only the physical map differs - CPC gate array, Next MMU slots 2/3, MSX mapper).
  Values >= 2 (to keep lower banks free, e.g. for a RAMdisc) currently behave like 1.
- Removed the compiler's auto-added Option Reserve &H4000, &H4000 for page/overlay classes. A
  page is not a reservation: declaring page/overlay classes no longer carves a hole on its own.
  A program that needs the window built round says so with Option Page <n>,... (n >= 1) or an
  explicit Option Reserve. Verified: compiling all 41 programs x 9 platforms with the pre-change
  vs post-change compiler gives byte-identical output, so nothing in the suite relied on it.
  (src/js/ntc_compiler.js: scanPages numeric-form parse; the auto-reserve block removed.)
- test/regress.sh: added the Option Page <n> checks (0 -> no hole, 1 -> reserved, zxn too, and
  the two refusals). docs/NTC.md documents the directive and the no-auto-reserve behaviour.
